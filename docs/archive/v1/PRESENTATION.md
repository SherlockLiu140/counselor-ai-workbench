# PRESENTATION.md｜HTML 汇报执行规范

## 汇报定位
优秀班主任经验分享，不做“AI 软件培训”。

核心主线：
**说话代替打字，流程代替 Prompt，本地保护数据，AI 释放时间。**

## 四个关键词
1. 语音输入
2. 工作流
3. Local First
4. 把时间还给学生

## 视觉要求
- HTML 代替传统 PPT
- 专业、克制、现代
- 不用蓝紫渐变
- 不要“科技大屏”视觉
- 少字、大标题、强对比
- 允许少量流程动画
- 动效服务于叙事，不做炫技
- 优先 16:9 桌面投影
- 适配 1920×1080 和 1366×768
- 字体优先系统中文字体，禁止远程字体

## 页面节奏
- 观点页：一句话
- 数据页：1 个核心数字 + 1 个解释
- 案例页：前后对比
- 法律页：只保留关键条款结论，不堆正文
- Demo 页：以真实界面为主
- 结束页：保持留白

## 演示安全
- 演示模式禁止加载真实花名册
- 所有 Demo 数据来自 DEMO_DATA.md
- 汇报页不展示任何真实学生信息
- 不在现场调用不稳定的外部 API
- 核心 Demo 必须断网可运行

## 演讲内容原则
避免：
- “AI 什么都能做”
- “用了 AI 就安全”
- “匿名后完全没有风险”
- “AI 可以判断心理问题”

推荐表述：
- “去标识化降低识别风险，但不等于完全匿名”
- “敏感信息先做本地处理，再决定是否需要外部 AI”
- “AI 辅助发现信息和整理工作，不替代班主任判断”
- “自动脱敏以后仍然需要人工复核”
