# 本地运行与验收

## 环境

Node.js 22.13 及以上（建议 Node 22 LTS 或 24），npm。依赖安装需要联网；运行后的文件解析不需要联网。不要通过 `file://` 打开构建文件，IndexedDB、模块 worker、剪贴板和 Service Worker 需要 localhost 或 HTTPS。

```sh
npm install
npm run dev
```

打开 `http://127.0.0.1:5173/workbench`。开发服务仅绑定本机，不开放局域网。

生产/离线验收：

```sh
npm run build
npm run preview
```

打开 `http://127.0.0.1:4173/workbench`，等首次应用资源缓存完成，然后断网刷新。生产缓存包含所有格式的解析器与 PDF worker/字库。开发模式没有 Service Worker，开发服务器重启或断网刷新与正式离线行为不同。

## 三分钟虚构演示

1. 打开 `/workbench?mode=demo`，选择“谈心谈话”或“隐私脱敏”。
2. 在“载入虚构案例”中选第一个案例；30 名虚构学生花名册已载入独立内存。
3. 点击“识别并进入人工复核”，查看陈晨与学号都映射为 S003，以及日期、手机号、宿舍、班级的处理。
4. 修改一处替换；或展开“新增敏感标记”，选择完整原文范围，输入替换内容并标记。
5. 检查剩余信息，勾选复核声明，点击“我已完成复核”。
6. 下载脱敏 TXT，或展开 Prompt 预览后复制。再次修改会撤销确认。

演示模式禁止导入真实花名册及文件。回到持久空间或 `/workbench?mode=session` 才能测试本地文件。测试材料全部由 `src/demo/data.ts` 和 `tests/fixtures.ts` 构造；不使用真实学生记录。

## 导入花名册

“本地花名册” → 选择 CSV/XLSX → 选择工作表 → 核对字段 → 确认本地导入。

姓名和学号必需。CSV 建议 UTF-8；Excel 的学号应以文本保存，避免前导零被上游 Excel 删除。多个班级可以放在同一张表，也可分别导入；同一学号资料更新保留代号，相同学号不同姓名拒绝覆盖。

正式材料输入支持 TXT、CSV、XLSX、DOCX 和文本 PDF。扫描 PDF、图片、老式 `.doc` 不支持 OCR。解析器将明确说明提取限制；不能把提取结果当作原文件所有内容的完整副本。

## 保存与清除

- 持久模式：花名册及映射存入当前浏览器的 IndexedDB；无加密保险箱。
- 会话模式：独立内存；刷新即清空；不读取、复制或删除原持久空间。
- 演示模式：独立内存且使用固定虚构数据；刷新重建虚构资料。
- 原始文件、文本、复核、Prompt 和当前字面规则均不写数据库，也不保存历史。
- 安全中心可以清除映射或清空当前空间。旧代号不再使用，已下载文件和系统剪贴板不受此按钮管理。

切换浏览器、域名或端口属于不同存储来源，不会自动迁移花名册。不要依赖浏览器存储作为唯一档案备份。

## 自测命令

```sh
npm test
npm run build
npx playwright install chromium
npm run test:browser
npm audit
```

浏览器测试自动启动生产预览服务，占用 `127.0.0.1:4173`，需先停止同端口的手动预览。测试安装 Chromium 只发生在开发准备期，不属于应用运行时请求。
